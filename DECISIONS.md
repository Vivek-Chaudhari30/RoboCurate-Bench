# Decision log

D-001 Build on LeRobot, exact-pinned (0.6.x). Why: required; mature train/eval/reward APIs. Rejected: robomimic codebase (better comparability with prior work, but reimplements LeRobot).
D-002 Unit of analysis = training run. Primary test: Welch t-test, cleaner runs vs pooled placebo runs (all subsets x seeds), same budget; Holm correction across cleaners within a task; bootstrap CI on the difference as secondary. Rejected: pooled-rollout binomial tests (pseudoreplication).
D-003 Results use only the final checkpoint at a fixed step count. Rejected: best-of-N checkpoint (selection bias; the failure mode reported by prior curation studies).
D-004 Fixed gradient-step count across all budgets and conditions. Rejected: fixed epochs (confounds compute with data size).
D-005 Seed count set by power analysis on M0-measured sigma, before any cleaner result. Floor 3. Rejected: fixed 3 seeds (MDE likely ~20pp, above most published effects).
D-006 Launch budget: keep 50% of episodes. 25% is a stretch goal if compute allows. Rejected: budget sweep (compute).
D-007 Eval seeds live only in configs/protocol.yaml. Cleaners that need rollouts (CUPID, Demo-SCORE) get a disjoint curation_seed_range and a declared rollout cap (100 per task, matching CUPID's simulation setting). Rejected: shared seed pool (eval leakage).
D-008 Ground-truth quality labels live in sidecar files that cleaners never receive. Used only for diagnostic precision/recall in reports.
D-009 Task A = ALOHA sim transfer-cube + ACT, human demos for M0 calibration. Rejected for M0: PushT + Diffusion (likely costlier training; revisit as Task B).
D-010 Package robocurate-bench, import name robocurate, CLI robocurate (pending PyPI check).
D-011 Defects must be physically consistent. Post-hoc injection is limited to pauses (frame holds), duplicate episodes and wrong task strings. Jitter and failed grasps are injected at execution time in sim (replay mode), so observations match actions. Rejected: post-hoc action noise (obs/action mismatch, unrealistic, trivially detectable).
D-012 Label-oracle reference condition per task and budget: selects episodes using the hidden ground-truth labels. It is NOT an entrant. It shows whether curation can help on this task at all. Rejected: no oracle (cannot tell "cleaners fail" from "task insensitive to curation").
D-013 Normalization stats are computed from each condition's training subset only, as a user would after cleaning. Pending: verify how LeRobot handles episode subsets. Rejected: full-dataset stats for every condition (leaks information about removed episodes).
D-014 Build order: CPU-testable software with a fake backend comes before GPU calibration. protocol.yaml values that depend on measurements stay TBD and block result runs.
D-015 Primary test stays Welch + Holm (D-002); the seed floor per condition is raised from 3 to 6 (amends D-005's floor). Why: at 3 seeds the null family-wise false-positive rate of Welch + Holm (7 cleaners, sigma_seed=0.06, 200 rollouts) is 0.090 > 0.07, because Welch's tail is ~2x too liberal at alpha/7 with 3 runs; at 6 seeds it is 0.060 (20000 simulated grids) with 0.98 power for a 20pp effect. Rejected: Student pooled t at 3 seeds (assumes equal cleaner/placebo run variance), exact permutation test at 3 seeds (power 0.79), 5 seeds (0.069, marginal).
D-016 (amends D-002; withdraws D-015's seed rule) The primary test accounts for subset-to-subset variance. A deterministic cleaner yields one subset, so its estimate carries irreducible subset variance. Statistic: (mean_c − mean_p) / SE, with SE² = s_sub²(1 + 1/K) + s_seed²(1/n_c + 1/(K·n_p)). Variance components come from a one-way random-effects ANOVA on the placebo runs (s_sub² truncated at 0). s_seed is pooled over the within-condition replicates of all conditions. Satterthwaite df; Holm across cleaners. Seeds are reallocated: placebo runs are shared across cleaners, so K (the number of random subsets) is the cheap lever, and per-cleaner seeds stay at the protocol floor (3) unless the power analysis says otherwise. Final n_c, K, n_p, and whether to add mixture replicates R, are set from M0's measured components before any entrant runs. Rejected: Welch on cleaner runs vs pooled placebo (FPR 0.42 at sigma_sub=0.04); more seeds per cleaner (does not shrink the sigma_sub term).
D-017 Calibration evals use calibration_seed_start = 300000 and never eval seeds. Eval-seed performance is not observed before the eval-v1 freeze. Training batch size = LeRobot's ACT default. Eval batch size is chosen for throughput, which is allowed only because per-episode seeds are batch-invariant (verified in source and by a GPU test).
D-018 Materialized subsets are cached by the content hash of their episode-id list and deleted after the last run that uses them. Results JSONs store the full episode-id list, so every subset can be rebuilt.
D-019 (amends D-016) The primary test always uses df = K−1 (the between-subset term, which dominates the SE, is estimated from K subset means). Result-mode runs require K >= 8 random subsets per budget; K < 8 is allowed only for calibration. Rejected: Satterthwaite df (anti-conservative at small K when s_sub truncates to 0); df = K−1 only on zero estimates (no power at K=4); K >= 8 with Satterthwaite (passes, but less power than df = K−1 at K=8). Parametric bootstrap is the fallback if the K >= 8 calibration misses its target.
D-020 Two entrant tracks. Selection track: select(dataset, budget) -> ids, compared to size-matched random subsets (D-016/D-019). Weighting track (e.g. RA-BC): the method assigns per-episode training weights on the full dataset. Its placebo is the same weight vector randomly permuted across episodes (K >= 8 permutations, seeds from protocol), compared with the same test, plus unweighted full data as reference. A weighting entrant may change only the weighting; every other training setting stays identical. Rejected: forcing weighting methods into top-k selection (misrepresents the method).
D-021 Selection ties are broken by sha256(salt || episode content hash) with a fixed protocol salt, never by episode index. The mixture builder must shuffle episode order deterministically by recipe seed. Rejected: index tie-break (correlates with source order in the mixture).
D-022 Cleaners declare resources: requires_rollouts (<= 100, on curation seeds only), requires_reference_policy (the full-data checkpoint of the first train seed, trained under the same protocol), requires_gpu. Selections and weights are computed once per (task, budget, mixture replicate) in a `prepare` stage, cached by input hashes, and their GPU-h is reported on the leaderboard as curation cost. Rejected: computing selections inside each training run (wasteful, and nondeterminism across seeds).
D-023 Our scorer, rcb-score v1, is fully defined in code and frozen (version string, documented formula) before any result run. Any later change ships as v2, reported separately. Rejected: iterating on our own scorer after seeing results.
D-024 (amends D-019) Result-mode runs require n_p >= 2 seeds per placebo subset (in addition to K >= 8). With n_p = 1, the placebo runs cannot separate subset variance from seed variance, and the test borrows s_seed from the cleaner's own runs, which breaks calibration. This restricts the design space to where the test is valid; the test itself is unchanged. It applies to the selection track and the weighting track (n_p >= 2 seeds per weight permutation). Rejected: parametric bootstrap now (more machinery; kept as the fallback if a K >= 8, n_p >= 2 cell fails).
D-026 (supersedes the D-016 SE formula; amends D-019, D-024; formally retires D-015's 6-seed floor) The primary test uses a balanced design: n_c = n_p = n, with n >= 3 (the protocol floor), and K >= 8 random subsets (or weight permutations). Under H0 the entrant's subset is exchangeable with a random subset, so the test is the exact prediction t-test: t = (mean_c − mean_p) / sqrt((1 + 1/K) · MS_between / n), where MS_between is the between-subset mean square of the placebo subset means times n, with df = K − 1. Holm across the entrants of a track. Variance components (s_sub, s_seed) are still estimated and reported as diagnostics only. Rejected: the unbalanced variance-components SE (anti-conservative when n_c > n_p); parametric bootstrap (unneeded given an exact test).
D-025 (amends D-020) Weighting-track placebo: permute whole per-episode weight curves across episodes. Resample each curve onto its target episode's length by normalized time (linear interpolation), then rescale all weights so the dataset-wide mean frame weight equals the original. This preserves within-episode weight structure and total effective data, and scrambles only which episode gets which curve. Rejected: raw permutation without resampling (length mismatch); within-episode shuffling (tests a different question).
D-027 Scratch on hokkaido is /share/datasets/robocurate (group-writable, the lab wiki's location for data over 10 GB; hokkaido has no /disk). It is network storage, so the M0 smoke test measures whether data loading bottlenecks training; the only allowed mitigation is DataLoader num_workers (speed, not results; recorded per run). Disk cap 200 GB; only final checkpoints are kept after their eval; D-018 cleanup is mandatory; df and quota are checked before first use. Rejected: the local system disk (98% full; the wiki forbids it); waiting for an admin to provision /disk (revisit if one appears).
D-028 (supersedes the weight-curve form of D-025) The weighting-track placebo permutes whole per-episode progress curves across episodes, resampled onto the target episode's length by normalized time, and feeds them through LeRobot's own RA-BC path, so both arms use identical LeRobot weighting code. The D-025 global rescale is dropped: LeRobot renormalizes weights per batch (rabc.py:232-233) and divides the loss by the weight sum (lerobot_train.py:162). Rejected: a custom launcher that injects precomputed weights (forks LeRobot's training loop); an upstream change (timeline).
D-029 CUPID stays disabled for ACT tasks: our loss-output influence passed the leave-one-out formula check but failed toybed sanity (AUC ≈ 0.5 even with an exact Hessian and 4,000 rollouts), consistent with first-order influence being unable to see a wrong-direction demo in a unimodal policy. It is tested in its native setting: a diffusion-policy toybed with the official output function. If it passes there, it is enabled only for diffusion-policy tasks. The ACT finding is reported as a limitation of influence-based curation with unimodal policies, never as "CUPID fails". Rejected: enabling it on ACT unverified; dropping influence methods.
D-030 Task B = PushT + Diffusion Policy, provided all three hold in the pinned LeRobot: the PushT env is runnable through lerobot-eval; lerobot/pusht loads without conversion; a CPU reset/render works. Why: the cheapest sim, CUPID's native policy family, and a different policy class from Task A (curation effects are architecture-dependent). Fallback if any check fails: a MetaWorld task with a scripted expert. Rejected: LIBERO / RoboCasa / RoboTwin (heavier sims aimed at VLAs).
D-031 Task A mixture recipe v1:
- 50 scripted + 50 human transfer-cube demos.
- 100 policy-rollout episodes from full-data ACT checkpoints at 10/30/60/100% of training (25 each, success and failure both kept; generated in the GPU phase).
- Post-hoc pauses and duplicates at the median rates measured in docs/defect_validation.md.
- Replay-mode jitter and failed-grasp perturbations on 20% of scripted episodes, with intensities set from the measured community jitter statistics.
- Wrong-task-string defects excluded for non-language policies (ACT ignores the task string).
- Episode order shuffled by recipe seed (D-021).
The recipe may change only before any entrant result exists; it freezes with eval-v1. Rejected: arbitrary defect rates not tied to real data.
D-032 Pre-registration: docs/preregistration.md states the hypotheses, primary test, design rules, entrants, tasks, mixtures and analysis plan before any entrant result. Vivek tags it prereg-v1 after review. Later changes are logged as numbered deviations in that file, never silent edits.
D-033 (amends D-027) Rollout-source checkpoints: for each task's M0 full-data seed-1000 run, keep the checkpoints at 10/30/60/100% of S. These are the D-031 rollout sources. Every other run keeps only its final checkpoint after eval. Rejected: keeping all intermediates (disk); a separate rollout-source training run (extra GPU).
D-034 The rollout-source policy is each task's M0 full-data seed-1000 checkpoint set. Data-generation rollouts use generation_seed_range 700000–799999, disjoint from eval (100000+), calibration (300000+) and curation (500000–599999) seeds. Rejected: generating with curation seeds (couples data generation to cleaner rollouts).
D-035 Diffusion Policy samples noise at eval, so per-episode outcomes may depend on batch composition. For diffusion tasks, eval_batch_size is fixed per task in protocol.yaml (TBD, set by M0 stage d, frozen with eval-v1). The GPU check requires determinism at that batch size only. ACT tasks keep the batch-invariance requirement. Rejected: patching LeRobot's sampler.
D-036 Influence entrant. CUPID's official configuration (agiachris/cupid@2941eba) stays disabled: AUROC ≈ 0.5 on both the MLP and the diffusion toybeds, diagnosed as a numerically singular TRAK Gram matrix. This is reported as a finding, with evidence, in docs/findings_cupid.md. The pre-registered influence entrant is gradsim-return: the plain gradient-similarity computation recorded in PROGRESS.md (CUPID's return-weighted rollout objective, compared with each demo's loss gradient by similarity, with no Hessian or Gram inverse). It has zero tunable parameters and credits CUPID and TracIn. It is enabled for a policy family only if it passes that family's toybed (AUROC >= 0.8). Rejected: damped CUPID with λ chosen on the toybed (a tuned knob published under another method's name).
D-037 Replay-mode jitter: σ is set so that injected episodes' high-frequency action power equals the community median among jittery episodes in docs/defect_validation.md, not the extreme of the measured range. The chosen σ and the matching evidence are recorded. The same rule applies to Task B wherever replay perturbations are used.
D-038 The project license is Apache-2.0 (matching LeRobot). Wrapped optional tools keep their own licenses and are never vendored.
